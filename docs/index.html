Fossil

Rebuild a project from its git history

Fossil turns a git repository's history into a step-by-step course. Each step is one commit, or a few tiny ones: the files that changed, the new functions, and the diff. You learn the project in the order it was built.

See a finished courseTry it on your repoGitHub

The example course is built from the history of my own diffbrief repo (12 commits). Titles come from commit messages. Nothing understands the code; if the first commit is huge, step 1 is huge.

Try it in your browser

Run this inside your repository and paste the output below. It is parsed in your browser and nothing is uploaded. The first run downloads the Python engine (about 10 MB).

git log --reverse --no-merges --date=short --find-renames --format="%x1e%H%x1f%an%x1f%ad%x1f%s%x1f%b%x1f" -p > history.txt

Honest limits

  • It does not understand code. Titles are commit messages. "New functions" come from simple patterns (Python, JavaScript, Go, Rust, Java and similar) and can miss or misfire.
  • The history decides the quality. Messy history ("fix", "wip") makes a weak course, and a giant first commit makes a giant step 1.
  • Tiny commits are merged and steps are capped (30 by default). Merging loses detail.
  • It never runs the code and does not check that each step works on its own. Binary files are only listed.
  • Long diffs are cut at 400 lines per file.
